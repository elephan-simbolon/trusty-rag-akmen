# Roadmap: v1.1 Knowledge Protocol Engineering

## Overview

Milestone v1.1 upgrades Trusty RAG Akmen from a textbook Q&A tool into a consulting-grade assistant through Knowledge Protocol Engineering (KPE). Three phases deliver the milestone: Phase 06 builds the generation layer (protocol registry, composable prompts, extended classifier, citation labels) with zero dependencies on new data — it works immediately on the existing accounting corpus. Phase 07 builds the retrieval infrastructure layer (source_domain backfill, payload index, domain-aware search, ingestion pipeline flag) that must be in place before any consulting content lands. Phase 08 ingests the 21 consulting/methodology books that populate the multi-domain corpus. This strict ordering prevents the most dangerous failure mode: a partial Qdrant backfill silently excluding all accounting chunks from domain-filtered queries.

## Phase Details

### Phase 06: KPE Core
**Goal**: User receives structured, framework-driven responses for management accounting queries — CVP, Variance Analysis, ABC, and other protocols guide answer shape without any extra LLM calls
**Depends on**: Phase 05.2 (v1.0 complete)
**Requirements**: PROT-01, PROT-02, PROT-03, PROT-04
**Success Criteria** (what must be TRUE):
  1. User sends a CVP or break-even query and receives a response structured with consistent section headers (## Jawaban Singkat, ## Analisis, ## Rekomendasi) derived from the matching protocol steps — not a generic prompt
  2. User sends any accounting query and the system selects the matching protocol (CVP, Variance, ABC, Transfer Pricing, Relevant Costing, Product Profitability, Budgeting, Cost Classification, or General) via rule-based keyword matching with zero additional LLM calls
  3. User sends an ambiguous query that matches no specific protocol and receives a coherent response using the General protocol fallback — no errors, no degraded quality
  4. Every response is generated from a modular composed system prompt (persona block + rules block + protocol steps + synthesis block) replacing the previous three-branch if/elif/else static prompts
**Plans**: 3 plans
Plans:
- [ ] 06-01-PLAN.md — Protocol Registry: ProtocolConfig dataclass + PROTOCOL_REGISTRY (9 protocols) + select_protocol()
- [ ] 06-02-PLAN.md — Modular Prompt Composer: compose_system_prompt() + RAGState.protocol_key + route_node + generate_response() refactor
- [ ] 06-03-PLAN.md — Tests + Validation: test_protocol_selection.py, test_protocol_prompts.py, update test_query_routing.py field count to 15
**UI hint**: yes

### Phase 07: Domain Retrieval Infrastructure
**Goal**: The retrieval pipeline can filter by source domain and all existing Qdrant points carry source_domain="accounting" — the foundation that makes multi-domain search safe and correct
**Depends on**: Phase 06
**Requirements**: RETR-01, RETR-02, RETR-03, RETR-04
**Success Criteria** (what must be TRUE):
  1. A retrieval call with domain_filter="accounting" returns only accounting textbook chunks; a call with domain_filter="consulting" returns only consulting chunks; a call with no filter returns both (reranker handles domain mix)
  2. Every existing Qdrant point has source_domain="accounting" in its payload — verified by client.count(filter=source_domain="accounting") equaling total collection point count before domain filtering goes live
  3. User sees [Sumber N] labels on accounting textbook citations and [Kerangka N] labels on consulting methodology citations in every response that includes consulting sources
  4. Running the ingestion script with --source-domain consulting correctly tags new consulting chunks at ingest time without modifying default behavior for existing accounting ingestion
**Plans**: 3 plans
Plans:
- [ ] 07-01-PLAN.md — Payload index + upload_batch source_domain field + backfill script (RETR-02)
- [ ] 07-02-PLAN.md — Domain-aware hybrid_search + ingest.py --source-domain flag (RETR-01, RETR-04)
- [ ] 07-03-PLAN.md — Wave 0 test files + citation label differentiation [Sumber N] / [Kerangka N] (RETR-03 + all Wave 0)

### Phase 08: Consulting Book Ingestion
**Goal**: 21 consulting/methodology books are fully indexed in Qdrant and retrievable alongside accounting textbooks, enabling the KPE protocols to pull from both the accounting corpus and consulting frameworks in a single query
**Depends on**: Phase 07
**Requirements**: INGEST-01, INGEST-02
**Success Criteria** (what must be TRUE):
  1. All 21 consulting books are ingested into Qdrant with source_domain="consulting" and each chunk carries complete metadata (book_title, chapter, page_start, page_end, author, source_domain) in the same schema as accounting chunks
  2. A query about a consulting framework (e.g., structured problem solving, issue tree, MECE) returns chunks from the consulting corpus with [Kerangka N] citation labels alongside any relevant accounting textbook citations
**Plans**: 2 plans
Plans:
- [ ] 08-01-PLAN.md — Pipeline extension: VLM gate (use_vlm param + --no-vlm flag) + author field (author param + --author flag) with Wave 0 test file (INGEST-01, INGEST-02)
- [ ] 08-02-PLAN.md — Operational ingestion: consulting PDF directory, per-book dry-run, full 21-book batch, UAT verification (INGEST-01, INGEST-02)

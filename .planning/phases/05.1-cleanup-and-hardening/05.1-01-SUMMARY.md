# Phase 05.1 Plan 01: Langfuse Wiring + Remove Double initialize_storages Summary

**One-liner:** Wired Langfuse CallbackHandler to `graph.ainvoke()` per query session and removed redundant `initialize_storages()` call from LightRAG factory function.

## What Was Done

### Task 1 — FLAG-2: Remove Redundant `initialize_storages()` (fix)

Removed `await rag.initialize_storages()` from `build_lightrag_instance()` in `src/knowledge_graph/lightrag_client.py` (was line 115, immediately before `return rag`).

**Why it was wrong:** `backend/main.py`'s FastAPI `lifespan` context manager already calls `await rag.initialize_storages()` after `build_lightrag_instance()` returns. The double call caused redundant storage initialization on every application startup.

**After fix:** `build_lightrag_instance()` constructs and configures the LightRAG instance and returns it. `lifespan` remains the single correct call site for `rag.initialize_storages()`.

### Task 2 — MON-01/MON-04: Wire Langfuse Callbacks (feat)

Made two targeted additions to `backend/main.py`:

1. Added import at top of file:
   ```python
   from src.monitoring.langfuse_client import get_langfuse_handler
   ```

2. In `query_sse`, immediately before `graph.ainvoke()`, added handler creation:
   ```python
   handler = get_langfuse_handler(session_id=session_id, user_id="default")
   callbacks = [handler] if handler else []
   ```

3. Updated `graph.ainvoke()` config to include callbacks:
   ```python
   config={"configurable": {"thread_id": session_id}, "callbacks": callbacks}
   ```

`get_langfuse_handler` returns `None` when `langfuse_enabled=False` or public key is absent, so `callbacks=[]` — zero overhead in environments without Langfuse configured.

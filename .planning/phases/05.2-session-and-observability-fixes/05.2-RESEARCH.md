# Phase 05.2: Session and Observability Fixes — Research

**Researched:** 2026-03-28
**Domain:** React session state, Langfuse v4 CallbackHandler, LangGraph MemorySaver, FastAPI request models
**Confidence:** HIGH (all findings verified against installed library source code)

---

## Summary

Phase 05.2 closes three v1.0 audit gaps by patching three focused code locations. The scope is narrow — six files total — with no architectural change required.

The most critical finding is a **Langfuse v4 API incompatibility**: the `CallbackHandler` constructor in the installed version (langfuse 4.0.1) does NOT accept `session_id` or `user_id` parameters. These attributes must instead be passed via `metadata` in the LangGraph `ainvoke` config dict, using special keys `langfuse_session_id` and `langfuse_user_id`. The RESEARCH.md for the previous phase described the old Langfuse v2/v3 API signature; that API no longer exists in the installed version. This changes the implementation approach for MON-01/MON-03.

The frontend fix (UI-02) is straightforward: replace `session_id: null` with a stable UUID generated once per browser session via `useRef` initialized with `crypto.randomUUID()`. The `sessionStorage` alternative is viable but adds unnecessary I/O for a single-user local app.

For `history_id`, the evidence strongly favors removal: the HistoryDB schema stores single-entry records (no turns table), the MemorySaver is keyed by `session_id`/`thread_id` (not history_id), and there is no lookup path from history_id to a MemorySaver checkpoint. Wiring `history_id` to `thread_id` would silently break conversation memory (each history-resumed query would start a fresh LangGraph thread rather than continuing the current session).

**Primary recommendation:** Fix all three issues in three isolated commits. Do not wire `history_id` to `thread_id` — remove it from the model.

## Architecture Patterns

### UI-02: Stable Session UUID in React

**Pattern: `useRef` with `crypto.randomUUID()`**

```typescript
// In useStreamingQuery.ts — add one line
const sessionIdRef = useRef<string>(crypto.randomUUID());
// Then in submit():
session_id: sessionIdRef.current,
```

**Why `useRef`, not `useState`:** `useRef` initializes once per component mount and never triggers re-render. `useState` also initializes once but carries unnecessary re-render semantics for an ID that never changes.

**Why `useRef` over `sessionStorage`:**
- `sessionStorage.getItem('session_id') ?? (() => { const id = crypto.randomUUID(); sessionStorage.setItem('session_id', id); return id; })()`  persists across React re-mounts but same behavior in a single-tab SPA
- `useRef` is simpler, no storage I/O, and sufficient for a single-user local app
- `sessionStorage` is worth considering only if the UUID must survive React tree unmounting within the same browser tab — not a requirement here
- `crypto.randomUUID()` is available in ES2022 browsers (all modern browsers since 2021) and in the project's TypeScript lib (`"lib": ["ES2022", "DOM", "DOM.Iterable"]`)

**Confidence:** HIGH — ES2022 lib target confirmed in `frontend/tsconfig.app.json`.

### MON-01/MON-03: Langfuse v4 Session Attribution

**CRITICAL: API changed from v2/v3 to v4**

Langfuse 4.0.1 `CallbackHandler.__init__` signature (verified from installed source):
```python
def __init__(self, *, public_key: Optional[str] = None, trace_context: Optional[TraceContext] = None) -> None
```

The `session_id` and `user_id` constructor parameters that existed in Langfuse v2/v3 are GONE in v4. Calling `CallbackHandler(session_id=..., user_id=...)` would raise a `TypeError`.

**v4 mechanism:** Langfuse reads `langfuse_session_id` and `langfuse_user_id` from the LangChain `metadata` dict passed to `on_chain_start`. At the root chain invocation (where `parent_run_id is None`), these keys are extracted and propagated via `propagate_attributes()`. This is verified from the installed `langfuse/langchain/CallbackHandler` source:

```python
# From langfuse/langchain/CallbackHandler (v4.0.1), lines 184-192
if "langfuse_session_id" in metadata and isinstance(metadata["langfuse_session_id"], str):
    attributes["session_id"] = metadata["langfuse_session_id"]

if "langfuse_user_id" in metadata and isinstance(metadata["langfuse_user_id"], str):
    attributes["user_id"] = metadata["langfuse_user_id"]
```

**`RunnableConfig` has a `metadata` key** (verified from `langchain_core.runnables.RunnableConfig` annotations):
- `metadata: dict[str, Any]`

**Correct fix — in `backend/main.py`, pass metadata in the config dict:**

```python
# backend/main.py — inside query_sse event_stream()
result = await graph.ainvoke(
    {
        "query": request.question,
        "conversation_history": [],
        "crag_iterations": 0,
        "crag_grade": None,
    },
    config={
        "configurable": {"thread_id": session_id},
        "callbacks": callbacks,
        "metadata": {
            "langfuse_session_id": session_id,
            "langfuse_user_id": "default",
        },
    },
)
```

**`langfuse_client.py` changes:** The `get_langfuse_handler()` function signature already accepts `session_id` and `user_id` parameters — but since the v4 constructor ignores them, these parameters are currently vestigial. The function body can be simplified to `return CallbackHandler()`. The session/user attribution is handled by the `metadata` in the config dict, not in the handler constructor.

**Confidence:** HIGH — verified by direct inspection of installed library source code.

### `history_id`: Remove, Do Not Wire

**Finding: `history_id` cannot be meaningfully wired to MemorySaver.**

The MemorySaver checkpointer in `build_phase3_graph()` is keyed by `thread_id` from `config["configurable"]["thread_id"]`. A LangGraph checkpoint thread represents an ongoing conversation in memory — it exists only while the server process is running. The `history_id` is a SQLite record UUID for a single completed query. The DB schema has no `turns` table and no link between a `history_id` and a MemorySaver thread.

Even if a mapping existed, passing `history_id` as `thread_id` would start a new MemorySaver thread (with empty memory) for each history-resumed query, not restore the original conversation.

The correct UX for restoring history is what already exists: `restoreFromHistory()` in `useStreamingQuery.ts` reconstructs the frontend chat messages from the history API response. It does not need backend MemorySaver restoration.

**Decision: Remove `history_id` from `QueryRequest`.**

This means:
1. Delete `history_id: str | None = None` from `backend/models.py`
2. No change needed in `backend/main.py` (the field is already unused — verified: `request.history_id` is never read)
3. In `frontend/src/hooks/useStreamingQuery.ts`, remove `history_id: historyId || null` from the JSON body (line 40)
4. Update `submit()` signature to remove `historyId?: string | null` parameter if it's no longer passed

**Confidence:** HIGH — verified by reading all relevant files.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead |
|---------|-------------|-------------|
| Stable per-session UUID | Custom ID generation logic | `crypto.randomUUID()` (built-in Web Crypto API) |
| UUID storage across renders | State variable or module global | `useRef` (React built-in) |
| Langfuse session grouping | Custom trace metadata injection | `metadata["langfuse_session_id"]` in RunnableConfig |

## Common Pitfalls

### Pitfall 1: Using the Old Langfuse Constructor API
**What goes wrong:** `CallbackHandler(session_id=session_id, user_id=user_id)` raises `TypeError: __init__() got unexpected keyword argument 'session_id'`
**Why it happens:** Langfuse v3→v4 removed constructor parameters in favor of metadata injection
**How to avoid:** Pass `metadata={"langfuse_session_id": ..., "langfuse_user_id": ...}` in the LangGraph `ainvoke` config
**Warning signs:** `TypeError` in `get_langfuse_handler()`; traces appear in Langfuse but without session grouping

### Pitfall 2: `crypto.randomUUID()` Called Outside `useRef`
**What goes wrong:** Each render generates a new UUID — every query gets a different `session_id`, MemorySaver creates a new thread, conversation memory is lost
**Why it happens:** `crypto.randomUUID()` inside the component body runs on every render
**How to avoid:** Initialize inside `useRef(crypto.randomUUID())` — the initializer runs exactly once per component mount
**Warning signs:** Follow-up questions do not reference previous answers; Langfuse shows a new session for every query

### Pitfall 3: Wiring `history_id` to `thread_id` Instead of Removing It
**What goes wrong:** Each history-resumed query starts a fresh MemorySaver thread — prior conversation memory is gone for that thread, and the real ongoing session's memory is silently ignored
**Why it happens:** Misunderstanding of what `history_id` is — it's a DB record ID, not a LangGraph checkpoint key
**How to avoid:** Remove `history_id` from the model; keep `session_id` as the sole conversation continuity key

### Pitfall 4: Test `test_handler_created` Fails After Langfuse Fix
**What goes wrong:** `test_langfuse_integration.py::test_handler_created` mocks `CallbackHandler` as a class and asserts the handler is returned. If `get_langfuse_handler()` is simplified (no longer passes args), the mock assertion may fail because `mock_callback_cls.assert_called_with(...)` checks for specific args.
**How to avoid:** The current test asserts `result is mock_handler_instance` — it does NOT assert call args. Verify the test still passes after the change. The session/user metadata is now in `main.py` config, which is covered by a new test.

### Pitfall 5: `noUnusedParameters` TypeScript strict check
**What goes wrong:** If `submit()` signature keeps `historyId?: string | null` after removing it from the JSON body, the TypeScript compiler raises `error TS6133: 'historyId' is declared but its value is never read` (strict mode, `noUnusedParameters: true`)
**How to avoid:** Remove the `historyId` parameter from `submit()` entirely, and update all call sites.

### Simplified `get_langfuse_handler` (no-arg constructor)

```python
# src/monitoring/langfuse_client.py
# The session_id/user_id parameters in the function signature can be removed
# since they are now passed via metadata in backend/main.py
def get_langfuse_handler() -> CallbackHandler | None:
    if not settings.langfuse_enabled:
        return None
    if not settings.langfuse_public_key:
        return None
    try:
        from langfuse.langchain import CallbackHandler
        return CallbackHandler()
    except Exception:
        logger.debug("Langfuse handler creation failed — continuing without tracing")
        return None
```

Note: The existing function signature accepts `session_id` and `user_id` params but they are currently dropped (`return CallbackHandler()` ignores them). The fix is to move attribution to the config metadata in `main.py`. The function signature can be simplified to remove the dead parameters, but this requires updating the existing test that calls `mock_get_handler.assert_called_once_with(session_id="sess-test-001", user_id="default")` in `test_langfuse_integration.py::test_query_sse_passes_callbacks_to_graph_ainvoke`.

**Call site in main.py must also be updated** from `get_langfuse_handler(session_id=session_id, user_id="default")` to `get_langfuse_handler()`.

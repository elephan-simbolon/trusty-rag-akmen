# Phase 05.2 Plan 02: Remove conversation_history Override from ainvoke Input Summary

Removed hardcoded `"conversation_history": []` from `graph.ainvoke()` input dict in `backend/main.py` so MemorySaver checkpoint restoration works correctly for follow-up queries, and updated all 5 matching invoke call sites in the conversation memory test suite to mirror the production pattern.

## What Was Done

**Root cause:** `backend/main.py` passed `"conversation_history": []` in every `graph.ainvoke()` call. Because `RAGState.conversation_history` is declared as `Annotated[list, operator.add]`, LangGraph applies the reducer by concatenating the input value (`[]`) with the checkpoint-restored history. An empty list appended to anything is still the original — but the input always replaces the initial state, meaning MemorySaver's checkpoint was being overridden on every new request. Follow-up queries therefore never saw prior turns.

**Fix applied:**
1. `backend/main.py` — deleted `"conversation_history": [],` from the `ainvoke` input dict (lines 74-79). The resulting input dict contains only `query`, `crag_iterations`, and `crag_grade`. For a brand-new `thread_id` (no checkpoint), LangGraph initializes the `Annotated[list, operator.add]` field to `[]` by default. For existing threads, MemorySaver restores the accumulated history from the checkpoint.
2. `tests/test_conversation_memory.py` — removed `"conversation_history": []` from all 5 `graph.invoke()` call sites across:
   - `test_conversation_history_accumulates_across_invocations` (2 calls)
   - `test_conversation_history_grows_with_each_turn` (1 call)
   - `test_conversation_history_contains_correct_roles` (1 call)
   - `test_different_thread_ids_have_isolated_histories` (3 calls)
   - `test_new_thread_starts_with_empty_history` (1 call)

`tests/test_phase3_graph.py` was intentionally left unchanged per plan specification — that file exercises full graph compilation, not production input behavior.

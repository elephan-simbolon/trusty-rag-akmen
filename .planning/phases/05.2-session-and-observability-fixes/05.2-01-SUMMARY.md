# Phase 05.2 Plan 01: Session ID and Langfuse v4 Observability Wiring Summary

**One-liner:** Frontend stable session UUID via useRef + Langfuse v4 metadata wiring in ainvoke config + dead history_id field removed from API contract.

## What Was Built

Closed three v1.0 milestone audit gaps in a single cohesive plan:

**UI-02 (conversation memory):** Frontend was sending `session_id: null` on every request, breaking LangGraph MemorySaver `thread_id` continuity across conversation turns. Fixed by adding `sessionIdRef = useRef<string>(crypto.randomUUID())` in `useStreamingQuery.ts`. The UUID is now generated once per browser session (component mount) and sent on every query, enabling stable per-session conversation threading.

**MON-01/MON-03 (Langfuse session attribution):** `get_langfuse_handler()` accepted `session_id`/`user_id` constructor args that were silently dropped (Langfuse v4 `CallbackHandler.__init__` only accepts `public_key` and `trace_context`). Fixed by removing those params and instead passing `metadata={"langfuse_session_id": ..., "langfuse_user_id": ...}` in `graph.ainvoke()` config — the correct Langfuse v4 mechanism for session grouping.

**Dead API field:** `QueryRequest.history_id` was accepted by backend but never read. Removed from model and request body.

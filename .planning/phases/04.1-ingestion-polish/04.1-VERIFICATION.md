### Per-Doc Breakdown (Terverifikasi)

| Komponen | Waktu | % | Sumber data |
|----------|-------|---|-------------|
| Queue wait (semaphore) | ~17-22s | 47% | `processing_start_time` vs LLM cache `create_time` |
| Post-LLM (embed + graph ops) | ~22s | 46% | LLM cache `create_time` vs `processing_end_time` |
| LLM call (DeepSeek) | ~3-8s | 7% | P0-P5 of pre-LLM distribution |

### Root Cause

**~47s/doc adalah overhead inherent LightRAG** — mayoritas waktu dihabiskan di:
- Internal graph merge dan entity deduplication
- nano-vectordb write operations
- Semaphore queue (sesuai best practice LightRAG: max_parallel_insert = max_async/4)

**Bukan masalah API rate limit.** SiliconFlow embedding punya 500K+ TPM (terpisah dari LLM). DeepSeek LLM tidak punya hard rate limit. Menaikkan `max_parallel_insert` di atas 4 bertentangan dengan rekomendasi LightRAG (risiko naming conflicts, crash data loss).

### Percobaan yang Gagal

| Percobaan | Hasil | Alasan |
|-----------|-------|--------|
| Ollama BGE-M3 local embedding | NaN error | Bug Ollama v0.13.5+ flash attention pada BERT (issue #13572). `OLLAMA_FLASH_ATTENTION=false` tidak memperbaiki di GTX 1660 Ti. |
| Ganti embedding provider | Tidak relevan | SiliconFlow embedding bukan bottleneck (500K+ TPM terpisah dari LLM) |
| Naikkan max_parallel_insert | Tidak dilakukan | Bertentangan dengan best practice LightRAG (Context7 docs) |

### Gaps Summary

**1 gap: POLISH-05 — Throughput goal not achieved**

- Target: 15-20 menit per buku
- Actual: ~3 jam per buku (792 docs, 46.9s/doc avg)
- Root cause: LightRAG per-doc processing overhead (~47s) is inherent to the architecture
- All feasible optimizations applied: DeepSeek LLM (no rate limit), gleaning=0, content filtering, max_parallel_insert=4
- Ollama local embedding attempted and failed (NaN bug)
- Cannot be resolved without replacing LightRAG itself

**Recommendation:** Accept as known limitation. Phase 4.1 delivered 1.67x improvement (4-9 jam → ~3 jam) plus crash-safe ingestion, content filtering, and resume capability. The remaining gap requires architectural change (replace LightRAG) which is a separate phase.

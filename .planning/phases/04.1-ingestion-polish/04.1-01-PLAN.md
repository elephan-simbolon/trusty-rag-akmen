**In `src/knowledge_graph/lightrag_client.py`, modify `build_lightrag_instance()`:**

1. Change `llm_model_max_async=4` to `llm_model_max_async=16` (line 86). Rationale: SiliconFlow L2 tier supports ~500K TPM / ~2K tokens per call = 250 calls/min. max_async=16 is safe with max_parallel_insert=4 (each doc makes ~2 LLM calls with gleaning=0, so 4 docs x 2 calls = 8 concurrent, well within 16).

2. Add `max_parallel_insert=4` as a top-level constructor argument (NOT in addon_params). This controls how many documents are processed concurrently via an internal asyncio.Semaphore.

3. Add `entity_extract_max_gleaning=0` as a top-level constructor argument. Default is 1 (from LightRAG constants.py DEFAULT_MAX_GLEANING=1). Setting to 0 eliminates the second "gleaning" LLM call per chunk, halving LLM calls.

4. Remove `"insert_batch_size": 10` from `addon_params` dict. This key is silently ignored by LightRAG v1.4.11 — addon_params only uses `language` and `entity_types`.

5. Update the docstring to reflect the new parameters. Replace mentions of "50-chunk insert batch size" with accurate description of max_parallel_insert and gleaning=0.

The resulting constructor call should be:
```python
rag = LightRAG(
    working_dir=settings.lightrag_working_dir,
    llm_model_func=_llm_model_func,
    embedding_func=embedding_func,
    llm_model_max_async=16,
    embedding_func_max_async=8,
    max_parallel_insert=4,
    entity_extract_max_gleaning=0,
    addon_params={
        "language": "English",
        "entity_types": ACCOUNTING_ENTITY_TYPES,
    },
)
```

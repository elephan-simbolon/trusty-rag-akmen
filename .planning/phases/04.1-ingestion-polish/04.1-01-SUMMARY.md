## Accomplishments
- Fixed `llm_model_max_async` from 4 to 16 — supports ~250 LLM calls/min on SiliconFlow L2 tier
- Added `max_parallel_insert=4` as top-level constructor arg (it was absent; silently ignored in addon_params)
- Added `entity_extract_max_gleaning=0` — eliminates second gleaning pass, halving LLM calls per chunk
- Removed `insert_batch_size` from `addon_params` (silently ignored by LightRAG v1.4.11)
- Added 4 new regression tests; all 9 tests pass (5 existing + 4 new config assertions)

## Files Created/Modified

## Decisions Made
- `entity_extract_max_gleaning=0` chosen to halve LLM calls — default=1 was causing a second "gleaning" extraction pass per chunk with no measurable quality gain on accounting domain
- `max_parallel_insert=4` is the top-level control for document concurrency; plan research confirmed it is NOT honored inside `addon_params`
- `llm_model_max_async=16` is safe headroom: with gleaning=0 and 4 parallel inserts, peak = 4 docs x 2 LLM calls = 8 concurrent, below the 16 limit
- `insert_batch_size` removed from addon_params entirely — keeping silently-ignored config keys causes confusion for future maintainers

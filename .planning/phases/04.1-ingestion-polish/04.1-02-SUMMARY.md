## Decisions Made

- Content filtering applied BEFORE audit_mode cap: `filtered[:50] if audit_mode else filtered` — ensures the 50-chunk sample reflects only ingestion-worthy content types
- `patch.object(graph_ingestion_module, 'build_lightrag_instance')` used instead of string-path patch to avoid module reload breaking the mock context during test collection
- `resume_lightrag_ingestion()` calls only `apipeline_process_enqueue_documents()` — never re-enqueues. Pitfall 1 in RESEARCH.md documents why: re-enqueueing already-PROCESSED docs creates FAILED [DUPLICATE] records that inflate the failed counter
- `finalize_storages()` called both per enqueue batch (crash-safe) and in finally block (cleanup). Two calls for a single batch is expected behavior per design.
